## 固定合成工具名与隐式缓存（2026-10-16，main 源码更新）

起因是用户反馈开启抗截断后缓存率很低。合成工具名改为固定的 `router_emit`，“继续”与普通请求使用同一句工具描述。`npm run verify` 通过 211 项离线测试，新增断言：重复请求、流式参数和“继续”生成的工具声明完全相同；酒馆插件与 TauriTavern 路径里“继续”的工具声明与普通请求相同。

真实测试使用本机酒馆已保存的服务账号（只在测试进程内使用，未写入仓库、日志或回执），Gemini 3.7 Flash、global、Standard，原生 `generateContent`。每次最多 512 输出 token，串行发送，间隔 10 秒，失败即停，不重试。请求体由仓库代码生成，与插件和网关使用的抗截断准备和原生转换相同；“改前”组只把工具名换成每次新生成的 24 位随机名，并恢复旧描述，其余内容不变。各组使用不同文本，避免互相借用缓存。约 3 万 token 一轮的结果：

| 请求 | 提示 token | 命中缓存 token | 回复 |
| --- | --- | --- | --- |
| 改后：同一请求第 1 次 | 30,430 | 0 | `ALPHA`，restored=true，stop |
| 改后：同一请求第 2、3 次 | 30,430 | 24,501 / 24,501 | 同上 |
| 改后：下一轮（追加一问一答） | 30,442 | 24,493 | `BRAVO`，restored=true，stop |
| 改后：“继续”（已有 `BRA`） | 30,518 | 24,486 | 只补出 `VO`，restored=true，stop |
| 改前：同一请求 3 次，每次新随机名 | 30,567 / 30,571 / 30,567 | 0 / 0 / 0 | `ALPHA`，restored=true，stop |
| 对照：不带任何工具，同一请求 3 次 | 30,474 | 0 / 24,521 / 24,521 | `ALPHA` |

改前组的系统提示和聊天记录与第 1 次完全相同，仍然一点都没命中。可见工具声明也算在缓存前缀里，而且排在系统提示之前；名字一变，后面约 3 万 token 都无法复用。改后的命中量与不带工具的对照基本一致；“继续”和下一轮也命中了相同的前缀。

此前先用约 6 千 token 的提示词跑了一轮：改后、改前和不带工具的对照共 12 次请求全部为 0 命中，说明这个长度下隐式缓存本身没有触发，这一轮不能用来比较。同一轮验证了固定名下的非流式、下一轮、“继续”和原生流式还原（流式回复 `BRAVO`、restored=true、stop）。两轮共 23 次真实请求，合计 405,342 提示 token，其中 147,023 按缓存计。回执保存在本地忽略文件 `runtime/cache-live-*.json`。

证据边界：上述脚本对比只用了 Gemini 3.7 Flash、global、Standard 和服务账号鉴权，未测 Express、Flex 和 Priority。隐式缓存由 Vertex 尽力提供，间隔更久或请求被分到其他服务器时可能不命中。运行中的酒馆插件未更新。

### 真实酒馆测试（2026-10-16）

在临时目录另起一份 SillyTavern 1.19 副本，使用独立端口和数据目录，装上本次改动后的服务端插件。副本里只复制了用户实际使用的一套大型角色扮演预设（约 250 条提示词）、一张带 MVU 状态栏和表格数据脚本的角色卡、它用到的世界书和必要设置；卡和预设自带的酒馆助手脚本和正则照常加载。模型为 Gemini 4 Argon、global、Standard，抗截断为流式。测试前后核对了正式酒馆 88 个关键文件的哈希，全部一致，测试期间正式数据目录没有任何写入；副本和其中复制的凭据测后已删除。为取得请求体，副本中的插件临时加了一行记录代码，仓库代码不含这行。

| 请求 | 提示 token | 命中缓存 token | 结果 |
| --- | --- | --- | --- |
| 第 2 轮正文 | 126,078 | 0 | 约 2 万字，restored=true，STOP |
| 第 3 轮正文 | 136,432 | 0 | 约 2.1 万字，restored=true，STOP |
| 第 3 轮“继续” | 140,439 | 0 | 只补出 2,950 字（`suffix`），没有重写或重复，restored=true，STOP |
| 卡内脚本请求（剧情记忆召回、表格数据更新），3 次 | 134,728–141,231 | 0 | restored=true，stop |
| 第 3 轮正文请求体原样重发，输出上限 200 | 136,432 | 134,383 | 约 5 分钟后再发仍命中 134,383 |

第 1 轮（开局）和其后的一次脚本请求也正常还原，但没有记录到用量。

功能方面，正文、原生流式、“继续”、MVU 状态栏与变量更新，以及脚本发出的非流式请求全部正常。缓存方面，原样重发命中 98.5%，说明固定工具名后这份真实提示词可以被缓存；但在酒馆里一轮接一轮地对话，命中始终为 0。比较第 3 轮正文和“继续”的请求体：两者前 59,918 个字符相同，之后从每轮都会更新的“全局状态”表开始不同。这张表位于预设合并出的一大段提示词里，约在全部提示词的三分之一处。“继续”发出时，第 3 轮的缓存仍然有效（之后重发仍命中），却完全没有复用这段相同的开头。由此推断：Vertex 只在新请求完整包含上一次请求（除最后约 2 千 token）时才复用缓存，中途有任何改动，整份缓存都不能用。Google 文档没有写明这一点，这是根据实测得出的推断。

因此，每轮改动提示词前部的预设或角色卡（例如把状态表、按深度插入的世界书放在聊天记录之前），在正常对话中命中仍会很低。预计只有在几分钟内用相同提示词重发（如重新生成）时才会命中；酒馆内的重新生成本次没有实测。要让正常对话也命中，需要把每轮变化的内容放到聊天记录之后并尽量缩短，这属于预设和卡的结构，插件无法改变。这类卡附带的脚本每轮还会额外发出 1–2 次与正文规模相当的请求，它们同样不命中。

本轮在酒馆内约 10 次真实请求，记录到用量的 6 次合计约 81.5 万提示 token、4.1 万输出 token；脚本重发 6 次合计约 82.7 万提示 token，其中 81.4 万按缓存计。不含对话内容的用量回执保存在本地忽略文件 `runtime/tavern-cache-live-2026-10-16.json`。

## 独立网关 0.3.1 的真实请求

2026-09-22，在 Windows / Node.js 24.16.0 上使用临时回环实例和内存中的服务账号凭据，对 Gemini 3.8 Flash 发送三条固定文本请求，每条最多 512 个输出 token：

- Standard 普通非流式回复：HTTP 200、非空正文和 `stop`。
- Standard 流式抗截断：HTTP 200，原生参数流，454 个正文字符分 7 次读取到达，跨度 610 ms；`restored: true`、`stop`、`[DONE]`，实际档位 `ON_DEMAND`。
- Flex 原生严格 Schema：HTTP 200，输出符合封闭对象约束；未指定 `items` 的数组保留了 `null` 和嵌套数组，结束原因为 `stop`，实际档位 `ON_DEMAND_FLEX`。

三条请求的编号均与日志对应，`responseIntegrity.outcome` 都为 `complete`。测试未写入日常配置，临时监听已关闭。真实 Express、Priority、其他模型、Google 目录权限与 SillyTavern 界面不在本轮验收范围。

## 提取前的真实请求

2026-09-20，原 router 集成对同一流式传输核心运行了两条固定文本请求，各限制 512 个输出 token。非流式和流式均返回 HTTP 200、已还原正文和 `stop`。流式请求记录到 7 次带正文的读取，正文到达跨度为 911 ms，并收到 `[DONE]`。这些记录说明当时的 Vertex 请求确实分段到达。

上述历史结果来自原 router 集成，不能替代独立网关测试；0.3.1 的独立真实请求见上一节。默认 `npm run verify` 始终只使用本地模拟数据。服务的健康检查只说明进程可访问。

## 在自己的环境验收

完成 README 中的设置并启动服务后，运行：

```sh
npm run smoke -- --live
```

该命令会发送两条客户端请求，每次最多 512 个输出 token；开启提示词重试时最多提交 4 次上游请求，重试额外包含自定义文本。它检查普通回复的还原状态，以及流式回复的非空正文、`stop`、`[DONE]` 和还原标志；还要求至少两次带正文的读取，时间跨度至少 100 ms。最后用响应中的 `x-request-id` 核对 `/admin/events`。图片输入开启时，命令在发送任何请求前停止，因为图片请求走缓冲回退，无法通过流式检查。

验收日志只包含元数据。输出片段的到达次数受模型、网络和缓冲行为影响，单次结果不能保证每一条回复都以相同速度分段。

## 尚未证明的效果

短请求和模拟测试不能证明长篇内容不会截断。网关无法恢复模型未生成或网络未收到的内容。模型也可能直接返回普通文本，此时日志会显示 `restored: false`。

当前支持保存多个 Gemini 模型，不代表这些模型都已经过真实推理验收。没有为其他服务商、远程公开部署或不同客户端做兼容性保证。
