# 验收说明

中文 | [English](VALIDATION.en.md)

本页区分独立发布包的本地测试与提取前的真实上游验证。两者验证的范围不同。

## 独立发布包

`npm run verify` 包含语法、凭据和本机路径检查，以及本地测试，覆盖：

- JSON 分段、转义字符、Unicode、跨字节边界，以及解析大小限制。
- 原生 `partialArgs` 转换、普通文本回退、真实工具和 usage 保留。
- HTTP 鉴权、模型目录、字段校验、Google 地址限制及请求大小限制。
- 在模拟上游结束前，通过 HTTP 将正文交付给客户端。
- 不支持字段时保留参数并回退，已有工具和结构化输出跳过包装。
- 客户端取消、中途断流、上游错误、长度结束，以及不自动重试。
- 请求 ID 与验收日志对应，日志排除正文、提示词、随机工具名和凭据。
- GUI 会话、Host / Origin / CSRF 边界、凭据不回显、版本冲突、端口占用、保存/重启持久化和密钥轮换。
- Express API Key 的无项目端点、完整服务账号与项目覆盖、Flex/Priority 请求标头、原生普通/流式翻译和实际档位日志。
- 原生专用模式遇到不能保留的字段时在本地拒绝；不会自动降档或触发推理。
- 多模型别名与三种模式的普通/SSE 路由、上游 ID 与响应别名、非流式还原后转 SSE、真实工具及 JSON 绕过。
- 目录鉴权与分页、重复项、失败脱敏、循环页令牌和页数上限；旧配置迁移、多模型持久化及重启。

0.3.0 使用模拟目录在浏览器中批量保存两个上游的六个版本，验证重名拒绝、放弃修改、重载持久化及按版本测试。非流式抗截断一次性交付正文，流式抗截断分段交付，正常版本无包装。真实 Google 目录权限和各模型调用能力尚未通过这些模拟测试验证。

0.2.0 的浏览器验收使用独立临时配置和模拟上游：完成 Express/Flex 的保存应用、正文分段到达和还原状态显示，检查深浅主题和窄屏布局。它不证明真实 Express 凭据、Gemini 3.7 或某个账户的 Flex/Priority 权限有效。

测试使用本地模拟数据，不会调用 Vertex。CI 配置在 Linux 和 Windows 上分别运行 Node.js 22、24；实际运行结果以仓库的 [Actions](https://github.com/ken050210/vertex-streaming-anti-truncation/actions) 为准。

独立启动入口也已在 Windows / Node.js 24.16.0 上检查：健康接口返回 200，未鉴权的模型请求返回 401，鉴权后模型列表正确，监听地址为本机回环地址。该检查使用虚拟凭据，没有发送模型请求。

## 提取前的真实请求

2026-09-20，原 router 集成对同一流式传输核心运行了两条固定文本请求，各限制 512 个输出 token。非流式和流式均返回 HTTP 200、已还原正文和 `stop`。流式请求记录到 7 次带正文的读取，正文到达跨度为 911 ms，并收到 `[DONE]`。这些记录说明当时的 Vertex 请求确实分段到达。

上述结果来自原 router 集成。新独立 HTTP 服务的默认验收是本地模拟测试，未重复收费的 Vertex 请求，也未对独立包重做 SillyTavern 界面验收。服务的健康检查只说明进程可访问。

## 在自己的环境验收

完成 README 中的设置并启动服务后，运行：

```sh
npm run smoke -- --live
```

该命令会发送两条收费请求，各最多 512 个输出 token。它检查普通回复的还原状态，以及流式回复的非空正文、`stop`、`[DONE]` 和还原标志；还要求至少两次带正文的读取，时间跨度至少 100 ms。最后用响应中的 `x-request-id` 核对 `/admin/events`。

验收日志只包含元数据。输出片段的到达次数受模型、网络和缓冲行为影响，单次结果不能保证每一条回复都以相同速度分段。

## 尚未证明的效果

短请求和模拟测试不能证明长篇内容不会截断。网关无法恢复模型未生成或网络未收到的内容。模型也可能直接返回普通文本，此时日志会显示 `restored: false`。

当前支持保存多个 Gemini 模型，不代表这些模型都已经过真实推理验收。没有为其他服务商、远程公开部署或不同客户端做兼容性保证。
