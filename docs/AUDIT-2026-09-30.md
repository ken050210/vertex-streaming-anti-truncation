## 已复现并修复

| 优先级 | 问题与实际影响 | 修复与验证 |
| --- | --- | --- |
| 高 | 多个进程同时恢复过期配置锁时，可能删除另一个写入者的新锁；磁盘最终内容与返回成功的 revision 不一致。 | 串行执行锁恢复，并在恢复锁内重新检查。并发保存测试检查只有一个成功写入者、磁盘 revision 与其一致、其他写入者收到 409。 |
| 中 | 等待鉴权及上传请求体时，超时或断开连接不能及时终止等待；甚至可能在超时后进入上游调用。 | 将取消信号应用到这些等待阶段；不取消其他请求共享的令牌签发，取消后不再启动生成请求。 |
| 中 | 酒馆插件接受 `developer` 消息，但酒馆 Google 转换器会把它作为无效原生角色发送。 | 在提示词后处理前将其转换为 `system`，保持原输入不变。 |
| 中 | 酒馆内容数组内的 `tool_calls` / `tool_call_id` 未被识别为工具历史，可能混入合成正文工具。 | 前后端共用的跳过判断覆盖嵌入工具格式及消息级调用 ID；这些请求继续走酒馆原流程。 |
| 中 | 原生普通响应及工具流会丢失具体结束码；带 `candidates: []` 的提示词拦截可能被误报为流中断。 | 保留 `native_finish_reason`，同时保留兼容 API 的 `content_filter` / `tool_calls` 等语义；覆盖空候选拦截。 |
| 中 | SSE 使用 LF 后接 CRLF 的合法空行时，解析器会把相邻事件合并，导致 JSON 解析失败。 | 识别混合行结束符并处理跨字节块的 CRLF；覆盖所有有效组合及 UTF-8 分块。 |
| 低 | 重复打包只覆盖文件，已经删除或重命名的源码可能残留在安装包中。 | 先构建完整临时目录，再替换生成目录；检查路径边界及链接，并验证残留文件被清除、哈希清单准确、相邻文件不受影响。 |

配置锁恢复采用保守策略：若进程恰好在恢复过程中退出，遗留的 `settings.lock.recovery` 不会被自动抢占。README 提供了停止所有写入进程、备份配置后只删除该标记的恢复步骤。

## 后续优化建议

1. **统一发布版本和安装包。** 当前扩展和服务端版本仍为 `0.1.0`，下载文档链接仍指向最初 Release。下次发布应同步版本、更新日志、配套 ZIP 和哈希，并分别验证前后端更新，避免 Git 最新版与旧 ZIP 混用。
2. **提供有限且脱敏的上游错误详情。** 目前 HTTP 错误主要只保留状态和通用错误码。可按固定字段、长度限制与脱敏规则提供供应商错误类别、结束码及重试提示，帮助区分额度、权限、地区和模型错误；不直接透传任意错误正文或保存提示词。
3. **限制长期缓存。** OAuth 缓存用完整服务账号 JSON 作键，过期条目没有统一清理；HTTP dispatcher 按超时值缓存 Agent，配置多次变化时不会主动回收。建议增加有界淘汰，并在没有使用者后关闭连接池；需要覆盖令牌并发签发及进行中的流不受影响。
4. **先测量再优化流处理性能。** 当前原生事件会经过数层 JSON/SSE 转换。建议以长文本、不同分块大小测量首字延迟、CPU 和峰值内存，再决定是否合并转换阶段，保留现有完整性与取消检查。

## 核验依据与验收边界

- [SSE 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)允许 CRLF、LF、CR 行结束符；测试覆盖其混合形式。
- [Google Priority PayGo 文档](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/priority-paygo)明确给出 `shared` 与 `priority` 两个请求头一起使用的示例。现有实现符合该说明，本次没有依据本地注释改动请求头。实际上游档位仍应以响应的 `trafficType` 为准。
- 自动化检查能够证明模拟协议、配置并发和打包行为；不能证明真实 Vertex 权限、模型可用性、计费档位或长回复抗截断收益。真实模型对照验收仍需单独安排。
